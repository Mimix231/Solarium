# Phase 01 — Implemented Canon Block Architecture

**Applied to:** `Solarium[Bak].zip` received 2026-11-11.
**Scope:** Phase 01 ONLY, as specified in `02_PHASE_01_IMPLEMENTATION_ORDER.md`.
**Source archive SHA-256:** `7958cf9a210772dc40798bbe91d31169cd13826b7fb06059bbca07c032cf73c8`.
**Result:** Source refactor completed and focused compatibility verification passed. **A complete desktop build/native run is NOT certified** because third-party npm dependencies and Rust toolchain were unavailable in the execution environment.

## Implementation

1. Converted all **26** schema-1 block definitions from the old `src/spica/program.ts::blockRegistry` literal into separate `src/spica/blocks/<category>/<subcategory>/<block>.ts` modules, preserving IDs, versions, labels, target support, permission grants and searchable warehouse categories/tags. Schema-1 algorithm/execution code remains in its original modules.
2. Added `src/spica/blocks/{contracts,defineBlock,categories,registry,registry.generated,standalone}.ts` and `category-folders.json`. One-file-per-block source modules declare typed legacy contract ports, category ID, permissions, maturity, exact legacy execution adapter, tags, dependencies and source ownership. No false claims of individually reimplemented Graph V2 runtimes.
3. Added `scripts/generate-spica-registry.cjs` with AST-only literal metadata extraction, ID/folder checking, legacy fixtures, permission and target validation, dependency-cycle validation, forbidding of cross-block source imports, deterministic generation and `--check` drift detection. Missing/stale files or unsupported new schema-1 IDs cause a hard error.
4. Replaced `program.ts::blockRegistry` with a backward-compatible generated projection, retaining all 3 original recipes and their original public API.
5. Updated `warehouse.ts` to derive registered metadata from canonical definitions, not independent category/tag mappings. Added normalized descriptors in `src/spica/capabilities.ts` and a native draft+registered discovery/inspect facade in `src/spica/catalog/unified.ts`, preserving legacy warehouse APIs. Drafts remain metadata-only. The verified-executable count is **0 until actual evidence exists**, not an estimate from registered modules.
6. Preserved standalone export behavior: `emitTauri()` now inlines the same v1 block contract data into its generated `src/graph.ts`, so old standalone apps do not import the Solarium registry. Export owner files, the schema version and public APIs remain unchanged.
7. Added the original contract snapshot `tests/fixtures/spica-phase01-legacy.json`, the focused test suite, a dependency-independent TypeScript test runner and `npm` scripts. Registration check runs before development, type-check, build and tests.
8. Placed all 9 source roadmap Markdown files in the existing **top-level `spica/roadmap/`** folder. No new Spica tab or UI replacement was introduced; the dream overlay is Phase 02.

## Run on your Windows Solarium checkout

1. Open the root of the extracted repository.
2. Run `npm ci` (using your existing lockfile).
3. Run `npm run spica:registry:check`.
4. Run `npm run test:spica:phase01` (new focused tests).
5. Run `npm test`, `npm run check`, `npm run lint`, `npm run build`, and `npm run test:glitch`.
6. With Rust installed, run `cargo check --manifest-path src-tauri/Cargo.toml` and your normal Spica standalone verification/Quick Capture scenarios.
7. If any check fails, retain the full log and treat Phase 01 integration as pending; do not claim standalone native success from the focused checks alone.
