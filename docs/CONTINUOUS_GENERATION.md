# Solarium 0.1 — Native continuous generation

**Current behavior** (supersedes the original 2,048-token replay design):

- llama.cpp performs one uninterrupted streamed chat-completions request with `max_tokens: -1`. Reasoning and final output are generated by the same active inference execution; Solarium does not inject "continue your reasoning" user messages at 2,048-token boundaries.
- Solarium-managed llama-server is launched with `--context-shift`. The server reuses the loaded model and bounded KV context. Continued generation does **not** load another copy of model weights.
- vLLM streams in a single request using the output capacity available in the model's finite context. It will report reaching context limits rather than attempting an unreliable synthetic continuation of internal reasoning.
- `streamContinuousAnswer()` emits actual reasoning deltas through `onReasoning` and actual response deltas through `onAnswer`. `ThinkingPanel` displays these as one expandable thinking view, without chunk or cycle labels.
- The initial prompt is checked by `prepareGeneration()` and, when necessary, nonessential old chat turns or optional research material are excluded from the *temporary request only*.
- Reasoning-only results are preserved, with a factual warning if no final answer was emitted. No artificial reasoning timeout, special reasoning allowance, or replay/repair loop has been introduced.
- The user can still stop generation; genuine server errors and context limits can still end it.

**Limits:** A single server-side streaming request is not infinite model context. llama.cpp context shifting may discard earlier text as KV memory is reused; vLLM context has finite available capacity. Model weights, KV cache, temporary CUDA buffers and simultaneous vLLM/llama.cpp processes each have their own memory requirements.

See [Native streaming and reasoning-loop fix](NATIVE_STREAM_REASONING_FIX.md) for the failure diagnosis and test instructions.
